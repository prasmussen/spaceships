# Plan implementation evidence

The objective remains the complete seven-milestone game in `plan.txt`. It is not complete. The workspace began with only the plan and is not a Git repository.

## Implemented and verified

- **Flight/landing:** handwritten integer WAT, pinned WABT assembly/validation, frozen tuning, 60 Hz with two substeps, fixed memory, no imports/floating-point gameplay, checked-in trig table, gravity/inertia/fuel, cave polygons and shared render geometry, static grid, swept circle edge/corner collision, strict own-pad landings, refuel/launch, crash penalty and respawns.
- **Combat:** 256 stable projectile slots, inherited velocity, swept terrain/moving-ship collision, held-fire cooldown/lifetime, three-hit hull, all damage/deaths resolved after substeps, simultaneous trades, first-to-five/tied-winning-score rules, spawn protection, online matches across separate browsers and rematch.
- **Rollback foundation/laboratory:** two-tick delay, repeat-last prediction, pre-tick snapshots, 120-tick retention, separate complete/agreed frontiers, 12-tick speculation cap, late-input replay, conflict/window validation, and reliable repair simulated independently from lossy latest-eight delivery. Interactive scenario controls cover RTT, jitter, loss and outages.
- **Replays:** online capture during play and final capture on leave/end, reconstruction checked against confirmed match state; versioned identities, initial state, final confirmed paired inputs, periodic checkpoints, exact validation, seeking, JSON export/import. Tests reject incompatible identities, malformed inputs and forged checkpoints.
- **Events/diagnostics:** deterministic tick/entity/index event IDs, presentation event records outside snapshots, deduper utility, frozen diagnostic bundles on agreed-hash mismatch, one designated-player-0 recovery and abort on repeated mismatch. Real networking uses diagnostics and recovery. Event IDs now deduplicate bounded particles and optional synthesized sound; online frame batches collect events from catch-up and rollback execution.
- **Verification:** 87 Node tests pass; production TypeScript/Vite/WASM build passes. Collision tests include 20,000 analytic sweep comparisons and 4,000 grid/full-scan comparisons. Rollback tests cover 0–200 ms RTT, jitter/reordering/duplicates, 20% loss and outages; interactive lab also passes 50% loss with a three-second outage.
- **Browser checks:** the reusable `node tests/browser.mjs --all-engines` checks Chrome WebGPU flight/landing, saved controls, lab execution, replay seek/download/re-import, and 120,000-tick flight/cave replay hashes in Chromium, Firefox and WebKit at 30/60/144 presentation reads per simulated second. Native macOS extraction resolved a Playwright ZIP extraction stall under both Node 22 and 26.
- **Go lobby/signaling service:** expiring guest cookies, exact-origin WebSockets, identity/region handshake, invite rooms, ready states, regional queue, match IDs/epochs/seeds/slots, room-scoped bounded signaling, unverified finish reports, rematches, leave, ten-second reconnect retention, idle/session cleanup, short-lived TURN REST credentials and authenticated operational metrics. Go integration tests pass with the race detector. Startup verifies the served WASM digest against the manifest.
- **Peer packet foundation:** compact binary epoch/owner/tick/ack/latest-eight encoding and strict reliable-control payload validation, including bounded repairs and recovery snapshots. Real WebRTC uses separate unreliable gameplay and reliable control channels, with bounded queues, rate limits, repair, RTT-based start scheduling and content checks.
- **Go browser verification:** `node tests/browser.mjs --lobby` uses the existing approved entry point to start/stop the service and check two independent browser guest sessions through invite, ready, signaling, finish, rematch and leave. It writes `artifacts/lobby-browser.json` and a server log. It also checks the complete invite UI with real WebRTC, each browser’s controls and leave. `--peer` checks independent rollback workers, shared agreed hashes, pause/resume, ten-second input-stall disconnects and build rejection.
- **Go replay validation:** `go run ./cmd/replaycheck replay.json` runs the shipped WASM through pinned wazero, verifies its digest, initial state and every checkpoint, and reports the resulting hash/score. JS-generated recordings and corrupted-recording rejection are covered by Go integration tests.
- **Graphics recovery:** device loss rebuilds the adapter/device, pipelines, buffers and bind groups from CPU data while retaining the camera and simulation. Browser tests destroy devices, force adapter unavailability, retry recovery, and verify simulation ticks continue. `artifacts/graphics-recovered.png` records the restored view.
- **Local TURN evidence:** `node tests/browser.mjs --turn` starts pinned coturn with temporary REST credentials from the Go service, forces both browsers onto relay candidates, exercises invite/control/leave, queue cancellation and two successive queue matches, and validates the downloaded replay in Go. A Linux relay Compose template and configuration guide are in `deploy/compose.turn.yml` and `docs/turn.md`; public deployment remains unverified.
- **Configurable controls:** keyboard-accessible Controls dialog remaps both players and restart/rematch, rejects duplicate bindings, stores validated browser preferences and updates prompts. Browser checks verify conflict handling, reload persistence, old/new key behavior and restoring defaults. Opening the dialog clears held inputs.
- **HTTPS/WSS packaging:** pinned multi-stage Docker build, non-root read-only app, Caddy reverse proxy and private app network. Explicit proxy CIDRs preserve client rate limits without trusting arbitrary forwarded headers. `node tests/browser.mjs --https` verifies container WASM identity, Secure cookies, WSS queue matching, WebRTC controls, wrong-origin rejection and leave. Go race checks pass. Deployment/operations instructions are in `docs/deployment.md`; public DNS/certificate/network acceptance still needs a host.
- **Complete matches:** normal-input flight fixture traverses the cave and wins 5–0 in 3,008 ticks. `--lobby --full-match` and `--turn --full-match` pass both confirmed winner HUDs, Go replay validation, rematch score reset and leave. This exposed and fixed early shutdown on a remote finish report; the receiver now waits for its own confirmed final inputs. See `docs/match-acceptance.md`.
- **Lobby reconnect:** failed session/config fetches retry inside the ten-second reconnect grace period; fetch and WebSocket setup have deadlines. Browser checks disconnect an active lobby socket, reject its first reconnect HTTP request, then verify restored membership and continued online status before leave/requeue.
- **Extended relay acceptance:** `node tests/browser.mjs --turn --soak` passed 660 seconds of real relay traffic, 39,796 agreed ticks, and three refreshes per peer (one forced path check plus two scheduled renewals). It then passed pause/resume, bounded disconnect and hash checks. `artifacts/turn-soak.json` records the completed hold.
- **Performance:** documented Apple M3 Max baseline; 20,000 ordinary tick samples and 500 actual 12-tick rollback samples. Current p99 is ~0.0018 ms per simulation tick and ~0.163 ms per rollback; including network/event/frame work, ~0.022 ms and ~0.194 ms. See `docs/performance.md` and generated artifacts.

## Remaining work against the original scope

1. Flight/landing: subjective controllability and course approach tuning remain a playable acceptance task. Numerical thresholds are versioned and boundary-tested. Full match/replay configuration is frozen in each artifact.
2. Local combat: core rules and rendered controls are tested, but extended human playthroughs remain useful evidence for game feel and natural full matches.
3. Rollback/presentation: extended visual/game-feel acceptance remains. Small position corrections now decay in a separate visual offset; large jumps, respawns and landings snap. Camera look-ahead is bounded and reduced-motion preference is available. Internet workers now run rollback, reliable repair and hash recovery; scores/winner come from agreed snapshots.
4. Internet: deploy TURN using the implemented credentials. Verify complete direct and forced-relay matches, including separate-network recovery. An eleven-minute TURN soak passed the original credential expiry with two scheduled renewals and continued agreed-state progress. Four-minute renewal and explicit restart now refresh credentials, retain the match timeline, and pass real TURN browser checks with the renewal deadline advanced. Direct loopback invite play, mismatch rejection, bounded input stalls and clean disconnects pass browser tests.
5. Casual release: queue and metrics are exposed in the browser. The How to play guide covers flight, landing, scoring and online setup. Cancellation, automatic stranger matching, flight, leave and requeue pass through real TURN in the browser. Local complete match/rematch acceptance passes. Remaining: public HTTPS/WSS deployment and separate-network acceptance.
6. Polish/validation: further lighting/accessibility refinement, deployment and operational docs. Go/wazero replay validation is implemented; see `docs/replays.md`. Keep gameplay independent of cosmetic load.

See `docs/acceptance-audit.md` for the requirement-by-requirement evidence and limits. Per-engine replay reports now retain artifact identity and are preserved independently across later browser runs.

The external internet/TURN/deployment acceptance gates still need actual evidence. No claim of full plan completion is made by the existing green tests.
